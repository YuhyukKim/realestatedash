# 금액 정밀도 (3단계)

## 원칙

- 수집/DB의 원본 금액은 정수 만원(`priceManwon`)으로 보관합니다. 1단계 수집 경로에서 이미 적용되었습니다.
- 공개 API의 기존 `price`는 억원 단위를 유지합니다. 예: 100,001만원 → 10.0001억원. API 단위나 DB 스키마를 바꾸지 않습니다.
- `monthlyRent`는 정수 만원이며 `price`와 단위가 다릅니다.
- 개별 거래·최근 매매/전세·기간 최저/최고 가격은 공통 포맷터로 만원 단위까지 표시합니다. 필터·정렬·차트 계산 전에 표시용 반올림을 적용하지 않습니다.
- 엑셀의 기존 최근매매가(억원) 값도 표시 문자열로 대체하지 않고 원래 숫자를 유지합니다.

## 표시 예

| 원본(만원) | API price(억원) | 개별 거래 표시 |
| --- | --- | --- |
| 100001 | 10.0001 | 10억 1만원 |
| 109999 | 10.9999 | 10억 9,999만원 |
| 9999 | 0.9999 | 9,999만원 |
| 100000 | 10 | 10억 |

월세 예: `보증금 1억 1만원 / 월 123만원`. 유효한 무보증금은 0원이며, 미확인/비정상 금액은 0원으로 대체하지 않습니다.

## 집계와 실제 거래 구분

- 시장 평균·중위가는 좁은 요약 카드에서 소수점 한 자리 억원으로 표시하되 `약`을 붙입니다.
- 차트는 기존 월별 중위값을 계속 사용합니다. 축은 요약 표시이며, 최고/최저와 툴팁의 금액 중위값은 만원 단위로 반올림하고 `약`을 붙입니다.
- 두 거래의 중위값이나 평균은 1만원 미만 단위가 생길 수 있어 실제 계약금액으로 오인하지 않게 구분합니다. 전세가율의 % 단위는 그대로 유지합니다.
- 긴 금액과 보증금/월세 표시는 좁은 카드에서 줄바꿈을 허용합니다.

## 검증과 운영 범위

포맷터 경계값, 잘못된 금액, 매매·전세·월세, 실제 거래 목록/차트 렌더링, 파서에서 받은 만원 단위 보존을 회귀 테스트합니다.
